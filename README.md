# tcp — The Chill Photographer

Визитка и фотоальбомы: Vite + React, публикация на GitHub Pages.

## Страницы

| Адрес | Что там |
|---|---|
| `/` | визитка: фото, имя, телефон, Albums, Telegram, Instagram, Save contact |
| `/albums/` | список альбомов |
| `/albums/<slug>/` | альбом; у альбома с разделами — первый раздел |
| `/albums/<slug>/<section>/` | остальные разделы альбома с разделами |
| `/puzzle/` | Puzzle Me: альбомы со скачиванием (`downloadable` не `false`); вкладка рядом с Albums в шапке `/albums/` |
| `/puzzle/<slug>/` | фото альбома без видео; `?photo=<файл>` — игра |
| `/puzzle/<slug>/continue/` | начатые и не собранные пазлы альбома, последний — первым; вкладка видна, пока такие есть |
| `/puzzle/<slug>/done/` | собранные хоть раз: на плитке число частей и время последней сборки; в игре — дата и прежние результаты. Повторная сборка («Play again») прежние результаты не стирает |
| `/contact.vcf` | файл контакта, собирается при `npm run build` из `site.config.json` и `avatar-400.jpg` |

Фото профиля — `photos-src/avatar.jpg` (вне git); `npm run photos` делает из него `public/avatar-400.jpg`, `public/avatar-1200.jpg` и значок вкладки: `favicon-32.png`, `favicon-192.png` (скругление углов как у иконок iOS), `apple-touch-icon.png` (квадрат, для иконки на экране «Домой» в iOS), `icon-192.png` и `icon-512.png` для `public/manifest.webmanifest`: с экрана «Домой» сайт открывается без интерфейса браузера; подпись под иконкой — `short_name` в манифесте и `apple-mobile-web-app-title` в `index.html`.

## Структура

| Путь | Что это | В git |
|---|---|---|
| `photos-src/<slug>/` | исходные фото альбома | нет |
| `content/albums.json` | список альбомов: slug, название, дата, обложка, ссылка на архив | да |
| `site.config.json` | адрес сайта, адрес фото (`photosUrl`), подпись автора, ссылки на соцсети | да |
| `photos-out/<slug>/` | уменьшенные копии по длинной стороне (640 и 1600 px WebP, 2048 px JPEG, ~440 КБ на кадр) и сжатое видео — результат `npm run photos`, выгружаются в R2 | нет |
| `src/generated/albums.json` | манифест с размерами фото — результат `npm run photos` | да |
| `worker/` | воркер Cloudflare: отдаёт фото и видео из бакета R2 | да |
| `.env` | ключи доступа к R2 | нет |

## Команды

```sh
npm run photos   # обработать фото из photos-src и выгрузить в R2
npm run upload   # только выгрузить photos-out в R2 (новые и изменённые файлы)
npx wrangler deploy --config worker/wrangler.jsonc  # развернуть воркер после правки worker/
npm run dev      # локальный сервер, http://localhost:5173
npm run build    # сборка в dist/ + отдельные HTML для превью ссылок
npm run preview  # просмотр собранной версии
node scripts/find-cover.mjs …  # найти кадр и его кадрирование по отпечатку картинки (инструкция в начале скрипта)
```

## Новый альбом

1. Положить фото в `photos-src/<slug>/` (`slug` — латиница и дефисы, станет частью адреса).
2. Добавить запись в `content/albums.json`. Порядок записей — порядок карточек на главной. `title` выводится как есть, на любом языке; интерфейс сайта — на английском. `cover` — имя файла обложки; `null` — первое фото.
3. `npm run photos` — обработка и выгрузка в R2; проверить в `npm run dev`.
4. Закоммитить `content/`, `src/generated/` и запушить — GitHub Actions опубликует сайт.

### Необязательные поля альбома

| Поле | Что делает |
|---|---|
| `"downloadable": false` | без скачивания: нет кнопок Download all и Download в просмотре, отключены правый клик, перетаскивание и долгое нажатие на фото. Файлы при этом доступны по прямым ссылкам — это защита от случайного скачивания, не от целенаправленного |
| `"sections": [{ "slug", "title", "dir" }]` | вкладки разделов. Фото раздела — в `photos-src/<slug>/<dir>/`; первый раздел открывается по адресу альбома |
| `"cover"` | имя фото альбома или отдельного файла в `photos-src/<slug>/`, которого нет среди фото альбома |
| `"coverPosition"` | какая часть обложки видна, если кадр не помещается в экран: `"50% 20%"` — ближе к верху кадра; по умолчанию `"50% 50%"` |
| `"titleSize"` | размер заголовка на обложке: `"small"` (по умолчанию) — 40 px, `"medium"` — 48 px, `"large"` — 62 px; на телефоне 34 / 38 / 48 px |
| `"coverDim"` | затемнение обложки, 0…1; по умолчанию 0.4 |
| `"lightbox": "light"` | просмотр фото на белом фоне |
| `"layout"` | раскладка сетки: `"masonry"` (по умолчанию) — колонки, кадры разной высоты; `"storyboard"` — ряды одной высоты на всю ширину: 3 кадра, если среди них есть горизонтальный, иначе 4 |
| `"spacing"` | промежуток между фото в сетке, px; по умолчанию 2. Как на образце: 2 — small, 20 — medium, 40 — large |

Видео (`.mov`, `.mp4`, `.m4v`) кладётся в ту же папку, что фото, и стоит в альбоме по имени файла среди фото. `npm run photos` сжимает его ffmpeg (нужен в PATH: `brew install ffmpeg`) в MP4 H.264, CRF 23 — 22 секунды 1080p занимают ~27 МБ; заставка в сетке — первый кадр. HDR с iPhone (HLG) переводится в обычный цвет.

Имена файлов в адресах транслитерируются (`Тело 0.jpg` → `Telo-0-640.webp`): пробел в адресе ломает `srcset`.

«Download all» собирает zip в браузере из JPEG 2048 px альбома — отдельный архив на хостинге не нужен.
`archiveUrl` — ссылка на zip с оригиналами (например, файл в GitHub Releases); при `null` кнопка «Оригиналы» не показывается.

Обработанные копии не удаляются при удалении исходника: лишние файлы в `photos-out/<slug>/` и в бакете удаляются вручную (`npm run upload` перечисляет лишнее в бакете).

## Пазл

- Фото 1600 px режется в браузере на 12 / 24 / 48 / 96 частей (на экране до 600 px — до 48), сетка — с клетками ближе к квадрату (`src/puzzle.ts`). Формы выступов задаёт `seed` игры.
- Части берутся из ленты внизу и перетаскиваются на поле. Отпущенная ближе трети клетки от своего места — встаёт на место и больше не двигается; иначе остаётся на поле, над лентой — возвращается в ленту. Пальцем в ленте: вбок — прокрутка, вверх — взять часть.
- Кнопка со звёздочками — бледное фото под частями.
- «Reset progress» под названием альбома (со второго нажатия) стирает игры и результаты всех фото альбома.
- Игра сохраняется в `localStorage` браузера, ключ `puzzle:<slug>/<файл>`, результаты сборок — `puzzle-results:<slug>/<файл>`: продолжается после закрытия страницы, на другом устройстве — нет. Прогресс виден на плитках сетки: `5 / 24` — начат, `✓ 24 / 24` — собран.
- В разделе пазла текст не выделяется: на телефоне палец при перетаскивании задевал подписи.

## Фото в Cloudflare R2

Фото и видео лежат в бакете R2 `tcp-photos`; отдаёт их воркер `tcp` на `https://tcp.olkrind.workers.dev` (`photosUrl` в `site.config.json`). Ключ в бакете — путь в `photos-out/`: `<slug>/<файл>`.

- Лимиты бесплатных планов: R2 — 10 ГБ хранения, 10 млн чтений в месяц; воркер — 100 000 запросов в сутки на все альбомы, сброс в 00:00 UTC. Сверх лимита воркер отвечает ошибкой 1027 — фото не загружаются до сброса. Воркер просит браузер хранить файлы 30 дней: повторный просмотр альбома лимит не тратит.
- Заменённый файл с тем же именем у вернувшихся посетителей обновится не сразу — до 30 дней.
- Ключи для выгрузки — в `.env` (Account API token, Object Read & Write на бакет `tcp-photos`); вход в wrangler для деплоя воркера — `npx wrangler login`.
- Свой домен вместо `workers.dev` (без суточного лимита и воркера): подключить домен к бакету в Cloudflare и сменить `photosUrl` — перевыгрузка не нужна.

## Публикация на GitHub Pages

- Адрес сайта задаётся одной строкой — `siteUrl` в `site.config.json`. Из его пути берётся `base` для Vite и роутера, из него же строятся абсолютные ссылки для превью в мессенджерах. Сейчас: `https://olkrind.github.io/tcp` (репозиторий `olkrind/tcp`). При переименовании репозитория или подключении своего домена меняется эта строка и адрес в `git remote set-url origin …`. Старые адреса `*.github.io/<прежнее имя>/` GitHub не перенаправляет — они отдают 404.
- Settings → Pages → Build and deployment → Source: **GitHub Actions**.
- Лимиты: сайт до 1 ГБ, файл до 100 МБ, трафик около 100 ГБ в месяц. Фото в сайт не входят — они в R2.
